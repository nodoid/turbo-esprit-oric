# Porting conventions (Spectrum Z80 -> Oric 6502)

This port is a routine-by-routine translation of Durell's Turbo Esprit
(ZX Spectrum, 1986).  The game logic and the 3D renderer are translated
faithfully, so the same inputs give the same game state as on the Spectrum.
Only what touches the hardware is re-done for the Oric: the screen layout and
colour, the keyboard and the sound (AY chip instead of the beeper).

## 1. Memory map

| Oric | Use |
|---|---|
| `$00-$FF` | zero page: the Z80 register file (`src/zx.s`) + per-module variables (segment `ZEROPAGE`, allocated by the linker) |
| `$0100-$01FF` | 6502 stack |
| `$0200-$0243` | `LOBSS` segment |
| `$0244-$0249` | IRQ/NMI jumps (do not use) |
| `$0300-$03FF` | I/O |
| `$0400-$04FF` | `BSS` segment |
| `$0500-$05FF` | BASIC loader (free once the game runs) |
| `$0600-$5AFF` | segments `STARTUP`, `CODE`, `RODATA`, `DATA` |
| `$5B00-$7BBD` | **Spectrum working RAM at the same addresses as on the Spectrum** (segment `ZXRAM`, initial contents `data/zxram.bin` from the original): bit-reverse table `$5B00`, lane grid `$5C00-$63FF`, 3D off-screen buffer `$6400-$703F` (Spectrum format, 32 bytes/row), colour buffer `$7040-$71BF`, sprite work buffers `$71D0-$72CF`, game variables and tables `$74F5-$7BBD`.  City maps sit at `$686B` at load time, exactly like the original. |
| `$7BBE-$97FF` | segments `CODE2`, `RODATA2`, `DATA2` |
| `$9800-$9BFF` | character set for the text lines (HIRES mode) |
| `$9C00-$9FFF` | `HIBSS` segment |
| `$A000-$BF3F` | HIRES screen (200 lines x 40 bytes) |
| `$BF68-$BFDF` | the 3 text lines under the HIRES picture (kept blank) |

Spectrum addresses `$5B00-$7BBD` are used as literal addresses in the 6502 code
(`lda $75F6`).  Anything the original kept at `$7BBE` or above (variables in
code, self-modified operands that are really variables, tables, sprites,
maps...) is **relocated**: it becomes a label in the module that owns it.

## 2. Names

* `ZPROC $xxxx` (macro in `zx.inc`) defines and exports `Z_xxxx`, the
  translation of the Spectrum routine/label at `$xxxx`.  Every routine that is
  called from another module or tested on its own must have one.  Other
  modules use `ZIMPORT $xxxx`.
* Relocated *variables* (RAM state that must match the Spectrum): `ZVAR $xxxx, n`
  (zero-initialised) or `ZLABEL $xxxx, n` followed by your own `.byte` data.
  They export `ZV_xxxx` / `ZVS_xxxx`, which the test harness uses to copy state
  in from the Spectrum and compare it afterwards.  Import with `ZVIMPORT`.
* Relocated *constant* data (tables, sprites, text): plain labels, preferably
  `T_xxxx` with the Spectrum address, exported if another module needs them.
  Pointers inside such data must be rewritten as label expressions (the
  data is generated by a tool, see section 7).

## 3. Registers and calling convention

* Z80 `A` <-> 6502 `A` at routine entry/exit.
* `B C D E H L IX IY` and the alternate set live in zero page:
  `zb zc zd ze zh zl zixh zixl ziyh ziyl`, `zb2 zc2 zd2 ze2 zh2 zl2 za2`;
  pairs are little-endian (`zc`/`zb` = BC, `zl`/`zh` = HL, ...), so
  `lda (zl),y` reads `(HL+Y)`.  `za`/`zf` are spare.
* Flags: Z80 carry <-> 6502 C, Z80 zero <-> 6502 Z when a caller tests them.
  Document any other result.
* Inside a module use whatever is fastest: registers in X/Y, private zero-page
  variables, constant addresses instead of `(ix+n)` when IX is always the same
  (e.g. `IX=$75E1` -> `lda $75F6`).  Only the cross-module interface must
  follow the rules above.
* Routines that take inline data after the CALL (`A4C9`, `A4D6`, `BA5F`,
  `BA6A`, `BA72`, `A977`, `A97C`) keep that form: `jsr Z_A4C9` followed by the
  original `.byte` stream; the callee pulls the return address, reads the
  data and returns after it.  Stream bytes stay in the Spectrum format; the
  graphics engine maps coordinates to the Oric screen.
* `ld a,r` (the original's random numbers) -> `GET_R` (macro, `zx.inc`).
  Tests replay the Spectrum's actual R values through it.
* Self-modifying code is fine (everything runs in RAM).  Self-modified bytes
  that hold *state* across calls should be `ZVAR`s so they can be compared.
* Interrupts: the 50Hz IRQ (`hw.s`) only drives sound and the frame
  counter `frames`.  It is always on.  Code that needs the Spectrum's
  `HALT`-style frame wait uses `frames`.

## 4. Keyboard

The Spectrum key table at `$7524` (J L K A S M T, 3 bytes each) keeps its
place, but each entry now holds `Oric matrix row, column mask, 0`.
`Z_F37A` (in `hw.s`) tests an entry exactly like the original: `zl/zh` ->
entry, returns Z set when the key is down and leaves `zl/zh` = entry+2.
`key_row` (X = row) returns the held columns of one matrix row; `any_key`.
Oric matrix (row: columns 0..7):

```
0: 7 N 5 V RCTL 1 X 3        4: SPACE , . UP LSHIFT LEFT DOWN RIGHT
1: J T R F -    ESC Q D      5: U I O P FUNCT DEL ] [
2: M 6 B 4 CTRL Z 2 C        6: Y H G E -    A S W
3: K 9 ; - -    -  \ '       7: 8 L 0 / RSHIFT RETURN - =
```

## 5. Screen

The Oric picture is the Spectrum picture shifted, not scaled:

* **Oric HIRES line = Spectrum y + 4** (Spectrum rows 0-191 -> lines 4-195;
  lines 0-3 and 196-199 stay black).
* **Oric pixel x = Spectrum x + 6.**  Spectrum x 0..233 is visible; the right
  22 pixels (only the A-pillar frame) are cut.  Byte column = (x+6) div 6,
  bit = `$20 >> ((x+6) mod 6)`.
* **Byte column 0 of every line is a serial attribute** (the colour of the
  line).  Rules for a line whose Spectrum colours are paper P / ink K
  (Oric colour numbers, see the table below):
  * K = black: column 0 = `$80 | (16 + (7-P))` (inverse video paper), pixel
    bytes are `$C0 | bits`  -> black on P.
  * K = white: column 0 = `16 + P`, pixel bytes `$40 | bits`.
  * otherwise: column 0 = `16 + P`, column 1 = K (ink attribute; column 1
    covers Spectrum x 0..5), pixel bytes `$40 | bits`.
  Colour changes inside a line need extra attribute bytes (each blanks 6
  pixels); keep them where the Spectrum picture has gaps.
* A pixel write must keep bit 7 of the byte it changes and must never touch
  a byte whose bit 6 is 0 (an attribute).
* Spectrum -> Oric colour numbers: `0 1 2 3 4 5 6 7` (black blue red magenta
  green cyan yellow white) -> `0 4 1 5 2 6 3 7`.  Oric has no BRIGHT and no
  FLASH; BRIGHT toggles (the indicator lamps) become a colour change.
* The 3D view (Spectrum rows 0-95, columns 0-27) is drawn by the original
  code into the Spectrum-format buffer at `$6400` with colours in the buffer
  at `$7040`; `S862E` (`view.s`) converts both to the Oric screen.
* The status lines (Spectrum character rows 22-23, y 176-191: PENALTY/SCORE
  yellow, messages green) go to the Oric's **text lines** under the HIRES
  picture (`$BF68`, 3 rows x 40 characters): Spectrum row 22 -> text row 0,
  row 23 -> text row 1, text row 2 blank.  Column 0 of each row is the ink
  attribute (yellow / green), Spectrum character column c (pixel x = 8c) ->
  text column c + 4 (the 32 columns are centred).  The character set at
  `$9800` (HIRES mode) holds the Spectrum ROM font, pixel columns 1-6 of each
  glyph (the Spectrum font leaves columns 0 and 7 blank).  The gfx engine
  routes text whose y is >= 176 there; HIRES lines 180-199 are unused.

## 6. Sound

`src/snd.inc`: `snd_fx` (effects S3-S11 of the R8 catalogue), `music_start`
/ `music_busy` (the two menu tunes and the start jingle), `snd_engine`.
Effects do not block.  The border flashes of the crash noise are dropped.

## 7. Data

`make extract` regenerates `data/` from the original tape `orig/TurboEsprit.tzx`
(not in git).  Each module that needs original data has its own generator
`tools/gen_<module>.py` that writes `data/<module>_data.s` (or `.bin`).
Generated files are committed so the game builds without the tape.

## 8. Testing

* `tools/buildtest.py NAME src/a.s src/b.s ...` builds `build/test_NAME.bin`
  from some modules, stubbing every missing symbol with an `rts`.
* `tools/zxref.py` runs the real Spectrum game (python `zx` package) and
  captures the full state (registers + 64K) on entry to and on return from any
  routine, plus the R values it read.
* `tools/sim6502.py` loads a test binary into a 6502 emulator, copies a
  Spectrum state in (identity range + `ZV_` variables + registers), calls a
  `Z_xxxx` routine and lists the bytes that differ from the Spectrum's state
  after the original routine.
* Each module has `tests/test_<module>.py` that captures samples from real
  play (several cities, random driving) and checks every translated routine.
  Run them with a Python that has `zx`, `py65` and `Pillow`.
